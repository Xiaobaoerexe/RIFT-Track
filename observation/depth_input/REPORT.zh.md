## 采用的加速与显存措施

1. 地形编码一次缓存，同一地形通过场景ID供多个机器人共享；每个FP32缓存约1.625 MiB。地形变化后创建新快照，避免反向传播读到被替换的地形。
2. 几何查询和两个网络联合`torch.compile`，固定形状分块，使用channels-last布局；最后一个不足整块的批次内部填充后裁回。
3. 展开过程按32张分块重算。前向保存位姿、索引和噪声key，反向恢复相同噪声并重算，避免长期保存所有射线和卷积激活。
4. 几何透射率累计改为经验证等价的log/cumsum/exp形式，减少反向开销。没有减少射线样本、分辨率或网络宽度。
5. 显式无状态噪声保证重算、分块与样本顺序一致；GPU输入输出，不在每帧做CPU搬运。
6. 保存可选编译缓存，并把它与可移植wheel分开。新输入形状仍可能触发编译，应在计时训练前预热。

安装包形式本身不会自动加速；主要收益来自计算图、布局、缓存和内存管理。普通前向TensorRT/ONNX引擎不作为此版本的主接口，因为训练需要对预测位姿反向传播。

## 精度选择及验证边界

默认使用IEEE FP32。最终编译路径对照未编译参考，在256个位姿上：共同有效像素平均差异0.000234毫米，最大0.227毫米；孔洞掩码无差异；位置和旋转VJP相对L2差异分别0.0211%和0.0167%。这些说明封装改写的一致性，不是模型对真实物理深度的预测精度。

BF16纯推理最快实测约41,249图/秒，512张一组增量峰值222 MiB。与FP32比较的平均共同有效深度差异0.579毫米，掩码差异0.0546%，但少量敏感像素可达到17.3厘米差异。BF16的位姿梯度对照未达到5%准则；另测TF32的旋转梯度差异为6.67%，也未达到该准则。故两者均没有作为训练默认精度。BF16高速配置见README，适合明确不需要反向的调用。

还测试了32/64/128/256/512分块、连续/channels-last布局、max-autotune和CUDA Graph配置；具体数据在`BENCHMARKS.json`。没有假定批次越大越快，也没有把没有实测收益的选项默认打开。

模型参数冻结，但输入位姿到输出保留一阶梯度。二值有效性和孔洞使用硬前向、平滑直通替代梯度；这不是二值函数的精确导数。不支持二阶求导。噪声随key变化，尚未标定真实传感器的时间相关性。

## 接入要求

```python
from go2_depth_input import DepthInputGenerator, noise_keys

depth = DepthInputGenerator()
cache = depth.prepare_scenes(height_atlases, scene_origins)
keys = noise_keys(trajectory_ids, frame_index, episode_ids=episode_ids)
image_m = depth.render_from_body(
    cache, predicted_body_position, predicted_world_from_body,
    scene_ids, keys, mode="recompute",
)
features = student_visual_encoder(image_m)
```

训练想象路径不要对机身预测位姿detach，也不要把生成调用包在no_grad中。回放重算应复用相同key；episode重置后更新episode_id；GRU记忆及相机帧率由主训练工程按时间对齐维护。本包不替主训练决定这些语义。
